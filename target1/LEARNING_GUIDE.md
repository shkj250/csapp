# Attack Lab · 看见调用栈与控制流

[总路线](../README.md) · [工具箱](../learning/TOOLBOX.md) · 原始依据：[attacklab.pdf](attacklab.pdf)、[README.txt](README.txt)。练习对象是本目录的 `ctarget` 与 `rtarget`。

本实验的五个阶段、允许的攻击范围和成功条件保持原样。指南不提供 cookie 值、偏移答案、gadget 地址或载荷。先完成 Bomb 的基础调试，再开始这里。

## 热身：不攻击，先画布局

在纸上把八字节整数按小端序排列，给每个字节标出地址递增方向。在独立 C 练习中观察一次正常函数调用的 `%rsp`、返回地址和参数，暂不制造越界。

过关标准：能分别解释“一个地址的数值”“这个数值的字节编码”“该地址处存储的数据”。这三者不能混在一起。

## 关键知识

| 概念 / Concept | 本实验要回答的问题 |
|---|---|
| 返回地址 / Return address | `ret` 从哪里取下一个执行位置，栈如何移动？ |
| 缓冲区越界 / Buffer overflow | 输入超过边界后覆盖了哪段状态？ |
| 代码注入 / Code injection | 数据中的字节何时会被当作指令执行？ |
| 返回导向编程 / Return-oriented programming, ROP | 现有指令片段如何连接，谁消耗栈数据？ |
| 字符串生存期 / String lifetime | 后续调用会不会覆盖你存放字符串的位置？ |

## 阶段 1：建立工具闭环与栈模型

```sh
objdump -d ctarget
gdb ./ctarget
```

在 GDB 中找到并反汇编 `getbuf`，观察正常输入前后的栈。通过真实指令计算栈帧，区分为缓冲区分配的空间与返回地址的位置；不能直接把“局部数组长度”当成偏移。

载荷文件以后自行创建；`hex2raw` 将十六进制文本转换成原始字节，不是把 ASCII 字符 `4`、`1` 原样传给目标。用独立练习文件写两个普通字节并转换，先确认表示方法。

过关标准：能画出从输入起点到返回地址的布局，并解释输入终止字节会带来什么影响。讲义特别提醒输入路径中的 `0x0a`。

<details>
<summary>提示 1：栈偏移怎样验证</summary>

分别记录函数入口和分配局部空间后的 `%rsp`，定位保存的返回地址。数出两者之间的字节距离，再用内存观察验证；一次成功猜测不算布局证明。

</details>

## 阶段 2：完成 ctarget 的三个阶段

按讲义完成 phase 1、2、3，每次只增加一个目标：改变返回目标、设置参数、提供可靠的字符串。先预测进入目标函数时的寄存器与栈状态，再实际观察。

你自己创建 `payload.txt` 后，转换与运行的形式是：

```sh
./hex2raw < payload.txt > payload.raw
./ctarget -q < payload.raw
```

本讲义的 `-q` 用于本地练习时不向评分服务器报告；课程提交按课程要求执行。本命令只有在你已经推导并创建载荷后才有意义，不保证它会成功。

过关标准：三阶段都正常报告成功；每阶段解释覆盖范围、控制流和参数来源。字符串阶段要确认零终止与后续调用的覆盖风险。

<details>
<summary>提示 2：跳转成功了，参数却不对</summary>

把进入目标函数的状态与调用约定逐项比较。整数值、字符串地址和字符串内容是不同的东西。观察后续函数的栈写入，确认你需要保留的数据仍然存在。

</details>

## 阶段 3：完成 rtarget 的两个阶段

读讲义的 gadget farm 范围和可用指令约束。`farm.c` 帮助理解，但最终地址与指令字节以 `rtarget` 二进制为准。不要把 `ctarget` 的绝对栈地址直接搬过来。

为每个候选片段建立表格：读取寄存器、写入寄存器、消耗的栈字节、下一次 `ret` 的来源、副作用。连接前先在纸上模拟完整链。

```sh
objdump -d rtarget
./hex2raw < payload.txt > payload.raw
./rtarget -q < payload.raw
```

过关标准：phase 4、5 成功，且能一步步解释数据如何到达参数位置；栈移动的累计量与实际一致。

<details>
<summary>提示 3：每段都看似正确，连接后失败</summary>

某段可能额外消耗数据，或写入 32 位寄存器时改变了对应 64 位值。按执行顺序重画栈指针，而不是只把 gadget 地址列成一串。检查采用的片段是否在讲义允许区域内。

</details>

## 完整验收与进阶

五个阶段用对应目标正常执行通过；每份载荷有自己的布局与状态推导。不要修改目标、直接调用成功函数或用调试器改状态代替验收。

进阶：解释栈随机化与不可执行栈分别影响哪类方法；给自己的正常 C 练习比较开启保护后的行为；把某条 ROP 链抽象成数据流图。学习重点是解释控制流为何可被数据改变。
