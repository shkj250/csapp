# Shell Lab · 从顺序程序走向异步世界

[总路线](../README.md) · [工具箱](../learning/TOOLBOX.md) · 原始依据：[shlab.pdf](shlab.pdf)、[README](README)、`tsh.c`、`trace*.txt`。

你实现的是带作业控制的 tiny shell，不是完整 Bash。当前 `eval`、内建命令、前台等待与信号处理等待实现函数全部保留。目录实际有 16 条 trace，原 README 中的“15 条”是历史说明。

## 热身：先在独立程序观察父子进程

写一个 `fork` 后父子各打印 PID 的小程序，再由父进程等待子进程。把一次运行画成两条时间线，思考谁可能先打印。再观察子进程终止与父进程回收是两个不同事件。

过关标准：能解释 `fork` 返回值、`execve` 成功后不返回、`waitpid` 收集退出状态；不再假设父进程总先执行。

## 关键知识

| 概念 / Concept | 需要形成的模型 |
|---|---|
| 作业状态 / Job state | FG 前台、BG 后台、ST 停止，与进程退出分别处理 |
| PID / JID / PGID | 系统进程编号、shell 作业编号、进程组编号 |
| 信号屏蔽 / Signal masking | 暂缓处理相关信号，保护作业表操作的时序 |
| 信号处理函数 / Signal handler | 异步执行；避免不安全库调用并保护 `errno` |
| 进程组转发 / Process-group signaling | 前台作业可能有多个进程，不能只通知组长 |

## 阶段 1：EOF、内建命令与前台任务

先读 `parseline` 和提供的作业表工具，确定已有能力。完成 EOF/quit、内建命令识别、基本前台执行与等待，暂不追求完整作业控制。

```sh
make
make test01
make rtest01
make test02
make rtest02
make test03
make rtest03
```

过关标准：正确退出、执行前台程序、等待后再读下一条命令。参考输出用于比较语义；PID 可能不同，不要求逐字符机械一致。

## 阶段 2：后台任务与回收

完成后台执行和 `jobs`，实现 `SIGCHLD` 回收。重点研究“子进程很快结束、父进程尚未登记作业”的交错，而非只测试长时间运行的命令。

运行 `make test04`、`make test05`，再与对应 `rtest04`、`rtest05` 对照。一个 SIGCHLD 不保证只对应一个需要回收的子进程；还需要区分停止、继续和退出。

过关标准：后台任务不会阻塞提示符，已退出任务及时移出作业表；能解释为什么只调用一次 `waitpid` 不够稳健。进入下一阶段前画出受保护的作业表更新区间。

<details>
<summary>提示 2：偶尔出现消失的作业或僵尸</summary>

在时间线上交换“父登记作业”和“子退出/信号处理”的顺序。明确哪些信号需要屏蔽，父子各自何时恢复屏蔽状态；也检查作业表在多个路径中的一致性。

</details>

## 阶段 3：停止、继续与进程组

依次验证：trace06–08 的中断/停止，trace09–10 的 `bg`/`fg`，trace11–13 的整组转发与恢复。每条用 `make testNN` 和 `make rtestNN` 对照。

操作前先写状态表：当前状态、事件、目标状态、是否应等待、是否应删除。停止不是退出；恢复后台与恢复前台的等待行为不同。

过关标准：信号仅作用于正确前台作业且覆盖整个进程组；背景任务不被误伤；停止作业仍出现在表中；`fg` 真正等待该作业。

<details>
<summary>提示 3：只杀掉了 mysplit 的一部分</summary>

核对进程组的建立时间和信号发送目标。PID 与 PGID 数值有时相同，却不是同一概念；根据接口语义确定你发送给单个进程还是一组进程。

</details>

## 阶段 4：错误处理与外部信号

跑 trace14 的非法参数/不存在任务，trace15 的综合场景，trace16 的其他进程发来的信号。不要把终端按键误当成唯一信号来源。

过关标准：错误消息与参考语义一致；错误输入不会破坏作业表；外部信号场景也正常。重复综合测试以观察时序问题，但重复通过不能作为无竞态的证明。

## 完整验收与进阶

```sh
make
for n in 01 02 03 04 05 06 07 08 09 10 11 12 13 14 15 16; do
    make "test$n"
done
```

以上运行全部测试，需逐项检查输出，命令退出码本身不等于语义通过。用对应 `rtestNN` 核对可疑项目，特别核查状态转换、输出和进程组行为。

进阶：为关键竞态构造两种执行顺序并解释保护机制；给前台等待写出检查条件与进入等待之间的时序分析；说明为何忙等、固定 sleep 和异步通知各有局限。通过测试后仍能证明作业表不会被错误时序破坏，才算掌握异步思维。
