# Bomb Lab · 让汇编成为可读的证据

[总路线](../README.md) · [GDB 工具箱](../learning/TOOLBOX.md) · 原始依据：[bomblab.pdf](bomblab.pdf)、[README](README)、`bomb.c`。

这里已有编译好的 x86-64 自学炸弹。`bomb.c` 展示流程，不包含完整阶段实现；不要尝试把它作为完整源码重新编译。目标是独立解释并通过六个阶段，保留目标二进制。

## 热身：调试自己的小程序

在独立练习目录写一个比较两个整数并返回较大者的函数，用 `gcc -Og -g` 编译，使用 GDB 观察参数、比较和返回值。再写一个数组求和循环，标出循环入口、回边、出口。

过关标准：知道断点、单步和继续的区别；能把比较后的一条条件跳转翻译成一句带条件的话。

## 关键知识

| 概念 / Concept | 观察方法 |
|---|---|
| 参数与返回值 / Arguments and return value | Linux x86-64 常见整数/指针参数从 `%rdi`、`%rsi`、`%rdx` 等传入，返回值常在 `%rax` |
| 条件码 / Condition codes | 先确定哪条指令最后设置条件码，再解释跳转 |
| 间接访问 / Indirect access | 区分地址计算与对该地址的读写 |
| 数据结构 / Data structure | 通过字段偏移、访问宽度和指针追踪推断结构 |
| 递归 / Recursion | 跟踪调用参数、终止条件和返回值如何组合 |

不要预设每关都是网上常见版本。以下按你遇到的结构补课；具体约束以当前二进制为准。

## 阶段 1：学会停下来

```sh
gdb ./bomb
```

在 GDB 中执行：

```text
break phase_1
break explode_bomb
run
disassemble phase_1
info registers
```

到阶段断点后先观察再继续；到 `explode_bomb` 断点说明失败路径已被选中，先记录原因，再退出或重新运行。断点不会自动让输入正确。

过关标准：能解释输入怎样传给第一关，指出成功路径与失败路径。不猜答案字符串，不把 `strings` 的输出当成成功的证明。

先找调用、比较、跳转三个类别。标出哪些分支通往失败，其他路径需要满足什么条件。遇到比较函数调用，观察其参数指向的实际数据。

## 阶段 2：每关建立一张证据表

每次只分析下一关，记录“输入格式 → 读取的数据 → 判定条件 → 失败分支 → 候选输入”。先确认转换成功数量等输入格式检查，再研究后面的算法。

若遇循环：写出循环变量、每次迭代的不变量、结束条件。若遇跳转表：区分选择索引和各分支自己的约束。若遇递归：先手算一个很小的输入调用树。

把已通过的输入逐行写入你自己的 `answers.txt`，再使用：

```sh
./bomb answers.txt
```

`bomb.c` 说明：文件读到末尾后会转到标准输入，所以可以继续分析后续关卡。GDB 中用 `run answers.txt` 重放。

过关标准：每通过一关都能从控制流推导答案；能指出一个只违反单项条件的反例，解释它会走向哪里。

<details>
<summary>提示 2：输入看起来对，为什么还是失败</summary>

检查输入解析了几个值、比较的是有符号还是无符号、循环是否多了一次、寄存器是地址还是值。先停在第一处分歧，不要反复运行到最后的爆炸输出。

</details>

## 阶段 3：从内存恢复结构

遇到表、字符串映射或链表时，先画字段与指针；逐步读取，不要把相邻的八字节都当成同一种类型。用 `x/16bx 地址` 看字节，用 `x/8gx 地址` 看宽单元；确定是字符串才用 `x/s`。

过关标准：能说明输入怎样改变遍历次序或查表位置，最终如何验证；解释结构时用字段含义，而不只列地址。

<details>
<summary>提示 3：不知道某块内存是什么</summary>

看访问宽度和随后用途：参与整数比较的字段与继续作为地址访问的字段，承担不同角色。先用一条真实执行路径验证结构假设，再扩展到其他元素。

</details>

## 完整验收与进阶

用保存的输入从头运行，六个常规阶段全部通过；保留每关的控制流图、关键条件和推导。不要修改二进制、跳过失败函数或用调试器强制改寄存器来代替正常输入验收。

进阶：把一关写成可读伪代码；重编译热身程序比较 `-O0` 与 `-Og` 的汇编；若自行发现额外路径，再作为选做分析，不替代六关要求。离开具体地址后仍能讲明算法，才是逆向能力的迁移。
